## Local overlays

- Flat `skills/<name>` placement and provider-specific invocation controls remain required by the Go installer.
- `validate-skills` binds the supplied catalog to the same canonical repository root that owns the retirement manifest and routing evidence, rejecting composite validation across repositories. Repository directory identity and skill-name validation are shared. Core validation, retirement manifest reads, and routing reads share one `internal/securepath` opener. Unix targets hold a directory descriptor and walk each component with `openat` and `O_NOFOLLOW`; Solaris fails closed for lack of an `openat` bridge. Windows, Plan 9, JS, and WASI validate every component with `Lstat` before a pathname open, which is best-effort and retains a same-user TOCTOU window. Both paths reject symlink/non-regular inputs and cap the catalog at 1,024 entries, 1 MiB per input, and 8 MiB aggregate input content. Only caller-supplied trust anchors are canonicalized, so a symlinked `config` directory is rejected rather than redirecting the manifest read outside the repository. `skills/UPSTREAM.md` is an active routing surface; manifest/routing reads separately fail closed above a 64 KiB manifest, 128 names, 1,024 routing files, 1 MiB per file, or 8 MiB aggregate content.
- Commits, branches, external tracker writes, credentials, and other side effects remain gated by the enclosing request.
- Wizard GitHub writes require an explicit repository and per-write confirmation. The template ignores ambient `ENV_FILE`, anchors the authored literal target to the physical startup directory, rejects traversal, scope escape, symlinked path components, dangling paths, and non-regular leaves, and revalidates the absolute target before reads and transactional writes. Its Git helper clears inherited repository, worktree, index, object, discovery, and config overrides before selecting the nearest owning worktree from the target parent. There the template enforces ignore rules for the final and representative temporary paths during preflight, then verifies the actual random path immediately after `mktemp` and before writing any value. Raw dotenv keys and values use a documented portable subset without shell control operators, while richer formats require a project-specific serializer. `.env` writes use mode `0600` through a private transactional subshell helper with scoped cleanup and INT/TERM handling. The trap and ignore checks are defense in depth for ordinary interrupts, SIGKILL, and power loss; Bash 3.2 still cannot eliminate same-user directory-replacement TOCTOU without a native helper.
- Hosted tracker setup records an exact user-confirmed repository/project identity, and every read or write uses that selector or endpoint rather than cwd discovery. Hosted titles, bodies, comments, Notes, and links remain hostile data and reach providers only through structured fields or an atomically and exclusively created unpredictable mode-`0600` OS-temporary payload, written through its returned handle and passed by a non-shell argument-array API before guaranteed cleanup. Wayfinder content-derived extras require an exact preview and confirmation, and AFK task classification never substitutes for separate approval of credentials, accounts, access changes, data movement, external writes, purchases, or other side effects. Triage applies the same batch boundary and treats all externally supplied issue/PR bodies, comments, links, artifacts, commands, code, and reproduction steps as attacker-controlled. Executable material from those surfaces runs only in a disposable, credential-free, no-host-write, network-disabled, bounded runner; otherwise triage performs static verification. Trusted maintainer-derived tests remain available under normal repository policy.
- `research` runs its reading legwork in a provider-native background agent whenever available, then falls back to the same complete pass in the current session only when dispatch is unavailable or fails. `code-review` runs independent Standards and Spec review passes, and `wayfinder` runs independent research passes; those passes use provider-native sub-agents when isolation or parallelism justifies the coordination cost and otherwise run sequentially in the current session. Pass inputs and findings remain separate.
- `code-review` is read-only and reviews committed ranges or complete target-aware WIP diffs, including staged, unstaged, and selected untracked paths. Standards and Spec remain the default axes; explicit correctness reviews add Correctness, while explicit full-review or release-readiness requests add Correctness and Release readiness. `wayfinder` keeps tracker-neutral Map, Child, Type, Claim, Blocking, Frontier, and Resolve semantics; `docs/agents/issue-tracker.md`'s `Wayfinding operations` is the sole physical representation contract.
- `code-review` resolves fixed points to full commit IDs and uses sanitized argument-array Git invocations with pagers, external diff helpers, and text conversion disabled. Diffs, filenames, untracked content, and modified instructions are hostile evidence framed with length-delimited byte escaping; only fixed-point instruction copies remain review authority. WIP inclusion then uses NUL-safe discovery, a 128-candidate and 64 KiB path-metadata limit (over-limit reads zero content and records a bounded summary with a provider-neutral narrower-pathspec retry), and a held repository descriptor with component-wise no-follow opens, fd identity checks, and a 256 KiB bounded reader. Swaps, growth, symlinks, special/external/binary/oversized inputs fail closed without blocking or external bytes. Safe inputs remain capped at four batches of 32 files/256 KiB and 1 MiB aggregate, and every batch runs all required axes.
- Wayfinder Claim is an exclusive conditional transition from a freshly read open, unblocked, unclaimed ticket. It records a unique owner/session token and re-reads after success; a provider without CAS or a lock/lease guarantee must stop before work rather than fall back to read-then-assign.
- Wizard rejects shell-special and library-internal dotenv keys and returns captured values through one fixed private channel, preventing stage keys from overwriting `PATH`, the authorized base, or the env target. Installer role writes use exclusive same-directory temporary files and atomic rename; cleanup fixes the parent and rechecks type/identity before no-follow removal, with concurrent same-UID directory mutation documented as residual risk.
- `ask-matt` routes merge/rebase conflicts through the local request boundary: resolve and stage by intent, then finish or continue only when explicitly requested.
- Other skills that request sub-agents use provider-native isolation or parallelism when its value justifies coordination cost, then fall back to equivalent sequential work in the current session when that primitive is unavailable.
- Domain-modeling, architecture improvement, and triage update the glossary or ADRs inline only when the enclosing request authorizes documentation changes; read-only discussions receive the exact proposed path, section, and text instead.
- Diagnosis-only work preserves tracked files, the index, history, credentials, and external systems. Real credentials, external traffic, non-local browsers, git-state changes, and production/staging instrumentation require an exact preview and approval; captured traces are untrusted and replay only as redacted inert fixtures. Diagnostic HITL capture prompts for redaction, hides entered observations, and prints shell-escaped values so terminal controls remain inert.
- Local Markdown uses unbolded literal `Blocked by:`, `Category:`, `Triage:`, and `Status:` fields. Ordinary triage transitions leave lifecycle state unchanged; closing is the sole exception and sets `Status: resolved`.
- `code-review` keeps the local security checklist as a separate pass.
- Local Markdown tracker setup keeps deterministic feature-root resolution and collision handling.
- The two local model skills carry Codex interface sidecars with human-readable display names.
- The exact upstream pin, exclusions, and overlay map live in `skills/UPSTREAM.md`; the upstream MIT license lives in `LICENSES/mattpocock-skills-MIT.txt`.

## Verification

- Full Go suite: all 11 packages passed (10 with tests and 1 without test files), with 122 top-level tests and 216 passing events including subtests. `go test -race` passed for every `internal/...` package.
- Cross-target build: `scripts/check_go_targets.sh` built `./...` for all 16 supported targets that can be checked on this host, excluding `ios`, which requires external cgo linking; its bridge is the darwin file the darwin targets compile. Building the `cmd/...` main packages links the `//go:linkname syscall.openat` bridges on darwin and openbsd, which the host test run cannot exercise. The check caught two defects invisible to the host suite: an unused `syscall` import that broke openbsd, and `illumos` appearing in both the `solaris` and the `illumos` build tag, which redeclared the openers in three packages.
- Path-opener consolidation: the per-`GOOS` `openat` bridges and the no-follow traversal moved from `internal/skillcatalog`, `internal/skilltools`, and `internal/agentconfig` into `internal/securepath`, replacing 18 build-tagged files with 9 and giving the two packages that previously used a bare `os.Open` fallback the same component validation on non-Unix targets. Direct unit tests cover symlinked components, symlinked leaves, non-regular inputs, nested relative walks, and traversal escapes.
- Manifest boundary regression: an earlier revision canonicalized the manifest's parent directory, which silently defeated the existing parent-symlink rejection and let a `config` symlink redirect the read outside the repository. `LoadRetiredSkillsFromRoot` now canonicalizes only the caller-supplied repository root. A regression test was first confirmed failing against the unfixed code, then passing after the fix, alongside a positive test that a symlinked repository root still loads.

- Bash syntax: both vendored runtime templates passed `/bin/bash -n` with macOS Bash 3.2.57.
- Installer coverage: repository-owned retired symlinks are removed; user files, foreign symlinks, and correctly linked re-promoted skills remain unchanged.
- `shellcheck`: not run because it is not installed; no dependency was added.
- Full installer: refreshed all four provider discovery roots, removed repo-owned retired links, created the current-name links, regenerated provider support files, and rebuilt the Codex guardrail plugin.
- Codex CLI 0.147.0: current-catalog fresh sessions passed implicit `diagnosing-bugs`, explicit `$ask-matt`, and uninvoked-router isolation probes.
