# Version And Dependency Closure

Use this reference before staging or committing changes that include dependency manifests, lockfiles, version metadata, generated dependency files, or release metadata.

## Principle

Dependency and version metadata is part of the logical commit closure when it is required to reproduce, build, test, run, or publish the change.

Do not commit only source logic while silently omitting required metadata.

## Common Files

Examples include:

- Go: `go.mod`, `go.sum`.
- Rust: `Cargo.toml`, `Cargo.lock`, `rust-version`, MSRV metadata.
- Python and uv: `pyproject.toml`, `requirements*.txt`, `uv.lock`.
- Node: `package.json`, `package-lock.json`, `pnpm-lock.yaml`, `yarn.lock`.
- Other ecosystems: version manifests, generated dependency indexes, release metadata, or toolchain version files.

## Commit Grouping

Default to the same commit when metadata changes are caused by, required for, or generated by the same feature or fix.

Use a separate commit only when:

- The dependency/version change is independent maintenance.
- The update is large enough to deserve separate review.
- A major or incompatible update requires migration work.
- The user explicitly asks for separated commits.

If relevance is unclear, list the candidate files and ask before excluding them.

## Compatibility Gate

Major or ecosystem-specific incompatible updates require compatibility lookup before commit readiness.

Check official release notes, changelogs, migration guides, package manager docs, or maintainer sources when available.

If compatibility cannot be verified, report `unknown compatibility risk` in the commit body, PR risks, or final summary.

## Ecosystem Notes

### SemVer

- Minor and patch updates are usually eligible to commit with the related feature or fix when they are part of the same logical change.
- Major updates require compatibility lookup and risk notes.
- Version declarations are signals, not proof that no behavior changed.

### Go

- `go.mod` and `go.sum` should be evaluated together.
- `v2+` modules may require module path or import path changes.
- `v0.*` versions do not imply stable compatibility.

### Rust

- `Cargo.toml` and `Cargo.lock` should be evaluated together.
- Cargo compatibility for `0.x` depends on the left-most non-zero component. For example, `0.1` to `0.2` is incompatible.
- `rust-version` or MSRV increases are compatibility risks.
- Feature or optional dependency changes may affect the public API.

### Python, uv, Node, And Other Ecosystems

- Manifest and lockfile changes should be considered together.
- Major dependency bumps need release-note or migration lookup when they affect runtime behavior.
- Large lockfile churn without an obvious manifest or tool change should be called out instead of treated as noise.

## Staging Rule

Use explicit paths. Do not stage broad patterns by default, but do include every metadata file that is required by the logical change closure.
